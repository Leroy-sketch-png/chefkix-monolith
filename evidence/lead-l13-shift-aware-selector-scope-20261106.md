## Bounded selector scope

1. **Operation:** A future shift-aware selector may choose among the outputs of already frozen scorers. It does not retrain a scorer, alter scorer ranks/scores, blend signals, or create a new candidate generator. The rejected SAG/dual-encoder work is not revived by this direction.
2. **Eligible features:** A routing input must be available to the system at request time, permitted for this use, and bound to a frozen/versioned source or request field before candidate outcomes are known. Missing or ambiguous feature values stay explicitly unknown. Exclude gold/reference identity, acceptability/adjudication labels, candidate-level human or judge outcomes, success/failure measured after scoring, validation/test partition or oracle-stratum labels, and any aggregate metric or result derived from the held-out case. A feature name alone is not proof of eligibility.
3. **Selection boundary:** Develop the feature schema and any routing rule only on Protocol v1's assigned validation-development partition; calibrate only on its assigned calibration partition where a calibration method is applicable. Freeze the exact feature inputs, rule/version, fallback, output semantics and analysis before test scoring. Test is reporting-only: no routing, threshold, arm, or hybrid revision from test outcomes. This decision does not turn validation diagnostics into confirmatory evidence.
4. **Matched cases and identities:** Every arm in a comparison must use the same frozen request-case cohort and request frame, with the same declared target/constraint context and adjudication rubric. Candidate lists may differ by arm, but every candidate is judged under the same predeclared validity rubric and identity policy. Cross-arm candidate alignment uses only exact canonical identity under the pinned vocabulary/map; no fuzzy or semantic aliasing. Unmatched and ambiguous candidate identities remain recorded and count against the fixed case/arm denominator; they are not silently removed. A comparison requiring candidate-level correspondence is ineligible until that correspondence is evidenced.
5. **Failures and abstention:** Preserve the original fixed case denominator for each arm. Missing, invalid, failed, and abstaining outputs remain explicit outcomes and are never dropped or recoded as successful empty sets. If a conditional-on-emission diagnostic is shown, report it separately beside the all-case denominator and abstention/failure counts. Use the existing Protocol status semantics: empty filtered pool is `abstain`; missing or incompatible calibration is `no_guarantee`; infinity is not coverage. No fallback silently substitutes another scorer.
6. **H5 equal-coverage comparison:** This remains exploratory and is unavailable until compatible matched arm outputs and valid candidate-level labels exist. The exact target levels/estimand and selector rule are deliberately not selected without those inputs. Any future operating points or tuning must be chosen only on the designated development/calibration material and frozen before test scoring; report each arm's achieved held-out coverage and set size on the same test cases with the unchanged denominator. Do not tune thresholds or select a hybrid to force equality on test. If common operating points or valid labels are absent, report the comparison as unavailable/incomparable rather than manufacture an equal-coverage result. This is not a guarantee of equal coverage.
7. **Guarantee and claim boundary:** An observed equal-coverage/set-size tradeoff is a descriptive exploratory result unless every applicable frozen calibration, exchangeability, labeling, and acceptance gate passes. A selector's uncertainty, abstention, or shift feature is not a safety, conformal, or user-benefit guarantee. No product or novelty claim follows from this scope decision.
